JSON (JavaScript Object Notation) es un formato de intercambio de datos ligero, fácil de leer y escribir para las personas y sencillo de procesar para las máquinas. Se basa en algo muy simple: pares clave–valor. Una clave (un texto) y el dato que le corresponde.

Aunque nació en el mundo de JavaScript, hoy es independiente del lenguaje: lo usan Python, Java, PHP y prácticamente cualquier tecnología. Está en todas partes —respuestas de APIs, archivos de configuración, e incluso en la forma de estructurar instrucciones para una IA— porque combina dos virtudes difíciles de tener juntas: es legible para un humano y predecible para una máquina.

Un valor en JSON solo puede ser uno de estos seis tipos. Toda estructura, por compleja que parezca, se construye combinándolos.

Cadena (string)

Texto entre comillas dobles. Siempre dobles, nunca simples.

"Hola mundo"

Número (number)

Enteros o decimales, sin comillas.

42  ·  3.14

Booleano (boolean)

Verdadero o falso reales, jamás entre comillas.

true  ·  false

Nulo (null)

Ausencia explícita de valor.

null

Objeto (object)

Colección de pares clave–valor entre llaves.

{"edad": 28}

Array (matriz)

Lista ordenada de elementos entre corchetes.

["rojo","azul"]

Las claves de un objeto son siempre cadenas (texto entre comillas dobles). Los valores pueden ser cualquiera de los seis tipos, incluidos otros objetos o arrays: así es como nacen las estructuras anidadas.

tipos.jsonjson
{
  "nombre": "Ana",
  "edad": 28,
  "activo": true,
  "segundoNombre": null,
  "colores": ["rojo", "verde", "azul"],
  "direccion": { "calle": "Principal", "numero": 12 }
}

JSON es estricto a propósito: esa rigidez es lo que lo hace fiable entre máquinas distintas. Estas son las reglas que más se incumplen.

  • Comillas dobles, siempre. Tanto las claves como las cadenas van entre " dobles. Las comillas simples no son JSON válido.
  • Las claves van entrecomilladas. edad: 28 no vale; debe ser "edad": 28.
  • Sin comas finales. Una coma después del último elemento (trailing comma) invalida el documento.
  • Sin comentarios. JSON no admite // ni /* */. Si necesitas notas, usa un campo extra como "_nota".
  • Booleanos y null en minúscula. Es true/false/null, no True ni NULL. Y undefined no existe en JSON.
  • Las fechas son cadenas. JSON no tiene tipo fecha: se representan como texto en formato ISO-8601.
✗ inválidono parsea
{
  'nombre': "Ana",
  edad: 28,
  "activo": True,
  "tags": ["a", "b",],
  "nota": undefined,
}
✓ válidocorrecto
{
  "nombre": "Ana",
  "edad": 28,
  "activo": true,
  "tags": ["a", "b"],
  "nota": null
}

Los seis errores de la izquierda: clave con comillas simples, clave sin comillas, True capitalizado, coma final en el array, undefined (no existe) y coma final en el objeto.

Dos operaciones resumen casi todo el trabajo con JSON: parsear (convertir texto JSON en un objeto manipulable) y serializar (el camino inverso, de objeto a texto).

En JavaScript

javascriptjs
// Texto JSON  ->  objeto JavaScript
const obj = JSON.parse('{"activo": true, "edad": 28}');
console.log(obj.edad); // 28

// Objeto JavaScript  ->  texto JSON
const texto = JSON.stringify(obj);

// Con sangría de 2 espacios para lectura humana (pretty-print)
const bonito = JSON.stringify(obj, null, 2);

// El 2.º parámetro (replacer) permite filtrar qué claves se incluyen
const filtrado = JSON.stringify(obj, ["edad"], 2);

En Python

pythonpy
# Con cadenas de texto
import json
obj = json.loads('{"activo": true}')   # texto -> dict
texto = json.dumps(obj, indent=2)       # dict -> texto

# Directamente con archivos
with open("datos.json", encoding="utf-8") as f:
    datos = json.load(f)                # archivo -> dict

with open("salida.json", "w", encoding="utf-8") as f:
    json.dump(datos, f, ensure_ascii=False, indent=2)  # dict -> archivo

Es muy común encontrar objetos dentro de objetos. El problema aparece cuando intentas acceder a una propiedad profunda y un nivel intermedio no existe: el programa intenta leer una propiedad de undefined y falla.

Encadenamiento opcional (?.) en JavaScript

El operador ?. detiene la evaluación y devuelve undefined si el valor anterior es nulo o no existe, en lugar de lanzar un error. Tiene tres formas:

encadenamiento-opcional.jsjs
const user = { nombre: "Ana" }; // sin "address"

// ✗ Esto lanzaría un error: no se puede leer "street" de undefined
// const calle = user.address.street;

// ✓ Con encadenamiento opcional, devuelve undefined sin romper
const calle = user?.address?.street;   // undefined

// Tres formas de usarlo:
obj?.prop;        // propiedad simple
obj?.[clave];     // propiedad dinámica (con corchetes)
obj.metodo?.();   // ejecuta el método solo si existe
!

No abuses del ?. Úsalo solo en propiedades que de verdad sean opcionales. Si lo pones en todas partes, puedes silenciar errores reales de programación y volverlos muy difíciles de depurar.

Method chaining (interfaces fluidas)

Una técnica de diseño donde cada método devuelve el propio objeto (return this;), lo que te permite encadenar llamadas que se leen como una frase. Reduce código repetitivo y mejora la legibilidad.

method-chaining.jsjs
// Cada método retorna "this", así se pueden encadenar
consulta.filtrar("activo").ordenar("edad").limitar(10);
  • Nombres de claves consistentes. Elige camelCase (duracionMs) o snake_case (peso_kg) y mantén el mismo estilo en todo el proyecto. Prioriza la claridad sobre las abreviaturas crípticas e incluye las unidades cuando ayude.
  • Dinero: nunca uses float. Los decimales flotantes arrastran errores de redondeo. Guarda el dinero como enteros (centavos) o con decimales definidos. Así, $19,99 se guarda como 1999.
  • Fechas en ISO-8601 y UTC. Usa siempre "2025-09-09T16:30:00Z". La Z indica UTC y evita líos de zonas horarias.
  • Evita la anidación excesiva. Más de 4 o 5 niveles vuelve el archivo difícil de leer y mantener. Si crece demasiado, divídelo en sub-recursos o referencia las partes por un id.
  • Distingue null de "ausente". Por convención, un campo que no aparece significa "desconocido o no aplica"; null significa que el campo aplica, pero se sabe que no tiene valor. Define qué significa cada cosa en tu proyecto.
i

Regla de profundidad agrupada. Agrupa la información por contextos lógicos (por ejemplo, sourceImage, presentationDetails) en vez de aplanar todo o anidar sin control. Lo verás en acción en el caso práctico.

JSON Schema es un estándar que actúa como un contrato documental: describe qué forma deben tener los datos para que quien los envía y quien los recibe respeten las mismas reglas. Reduce muchísimo los errores de integración en APIs y formularios.

Te permite declarar, entre otras cosas: qué claves son obligatorias (required), de qué tipo es cada una (type), sus rangos numéricos (minimum, maximum) y hasta patrones de texto con expresiones regulares (pattern).

esquema-alumno.jsonjson schema
{
  "type": "object",
  "required": ["nombre", "edad"],
  "properties": {
    "nombre": { "type": "string", "minLength": 1 },
    "edad":   { "type": "integer", "minimum": 0, "maximum": 120 },
    "correo": { "type": "string", "pattern": "^.+@.+\\..+$" },
    "activo": { "type": "boolean" }
  }
}

Un documento que cumple ese contrato:

alumno.jsonválido
{ "nombre": "Ana", "edad": 28, "correo": "ana@correo.com", "activo": true }

Para validar automáticamente existen librerías listas: AJV en JavaScript y jsonschema en Python.

  • Desinfecta los datos (anti-inyección). Aunque JSON es texto, conviene sanitizar lo que recibes para evitar inyección de código. Usa validadores formales como json-sanitizer y jamás uses eval() para analizar JSON en JavaScript: usa siempre JSON.parse().
  • Cabecera HTTP correcta. Si transmites JSON por una API, devuelve Content-Type: application/json; charset=utf-8 para que clientes y servidores lo interpreten bien.
  • Compacto en producción. El "pretty-print" (con sangrías y saltos de línea) es para leer, no para transmitir. En producción envía el JSON compacto y habilita compresión GZIP o Brotli para aligerar la transferencia.
!

La regla de seguridad número uno. Nunca uses eval() para parsear JSON. Ejecuta el contenido como código y abre la puerta a ataques. JSON.parse() es seguro y existe justo para esto.

Veamos las buenas prácticas en acción. Partimos de una orden escrita en lenguaje natural y la convertimos en un JSON limpio y predecible.

1 · La instrucción en texto plano

"El programa toma una imagen desde un enlace, la analiza para extraer su paleta de colores y su estilo, y con esa información genera automáticamente una presentación PPTX sobre las 'Tendencias de Diseño 2026', con un máximo de 10 diapositivas. El archivo final se envía a un correo específico."

2 · La misma instrucción, estructurada en JSON

generar-presentacion.jsonjson
{
  "actionName": "generatePresentation",
  "sourceImage": {
    "imageUrl": "https://ejemplo.com/estilo-base.jpg",
    "extractColors": true,
    "extractStyle": true
  },
  "presentationDetails": {
    "topic": "Tendencias de Diseño 2026",
    "outputFormat": "PPTX",
    "maxSlidesCount": 10
  },
  "deliveryConfiguration": {
    "deliveryMethod": "email",
    "recipientEmail": "usuario@ejemplo.com"
  },
  "requestDate": "2026-06-10T08:15:00Z"
}

3 · Por qué se estructuró así

  • Claves claras y consistentes. Todo en camelCase (imageUrl, deliveryConfiguration) y con nombres completos en vez de abreviaturas crípticas.
  • Tipos de datos correctos. Booleanos reales (true) para las instrucciones de extracción —no el texto "true"— y un entero (10) para el límite de diapositivas.
  • Fecha estandarizada. requestDate en ISO-8601 y UTC, para evitar problemas de zonas horarias.
  • Profundidad controlada. La información se agrupó por contextos lógicos (sourceImage, presentationDetails, deliveryConfiguration) sin pasar de 4–5 niveles de anidación, para que sea predecible y fácil de leer.
